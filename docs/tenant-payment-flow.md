# Процесс напоминания и добавления оплаты аренды арендатором (Tenant Payment Flow)

Данный документ описывает процесс отправки напоминаний об оплате аренды и пошаговый интерактивный флоу внесения платежей через Telegram-бота.

## 1. Отправка оповещения об оплате аренды
1. Ежедневно микросервис `Accountant` проверяет день оплаты аренды для активных арендаторов.
2. При наступлении расчетного дня отправляется событие `remind_rent_payment` с информацией о сумме и адресе квартиры.
3. Микросервис `Telegram Bot` форматирует уведомление для арендатора с кнопкой быстрого действия:
   - **Инлайн-кнопка**: `💳 Добавить оплату` (callback: `tenant_pay_{tenantId}_{rentAmount}`).

## 2. Пошаговый интерактивный флоу добавления оплаты

При нажатии на кнопку `💳 Добавить оплату` бот запускает 3-этапный мастер сбора данных о платеже:

```
[ Напоминание об оплате аренды ]
             │
             ▼ (Нажатие "💳 Добавить оплату")
[ Шаг 1: Выбор даты ] ────► "📅 Сегодня" ИЛИ ручной ввод "23.07.2026"
             │
             ▼
[ Шаг 2: Ввод суммы ] ────► "💰 11000 руб." ИЛИ ручной ввод численного значения
             │
             ▼
[ Шаг 3: Чек об оплате] ──► Загрузка снимка чека ИЛИ кнопка "⏩ Пропустить чек"
             │
             ▼
[ Создание платежа ] ─────► Событие `create_payment` -> Микросервис `Accountant` -> Статус `unconfirmed`
```

### Шаги флоу:
1. **Шаг 1 (Дата)**:
   - Сообщение с запросом даты платежа.
   - Опция быстрый выбор: кнопка `📅 Сегодня` (`payment_date_today`).
   - Ручной ввод в формате `ДД.ММ.ГГГГ` (например, `23.07.2026`).
2. **Шаг 2 (Сумма)**:
   - Подтверждение выбранной даты.
   - Опция быстрый выбор: кнопка с рекомендованной суммой (например, `💰 11000 руб.`).
   - Ручной ввод суммы числом.
3. **Шаг 3 (Чек)**:
   - Подтверждение даты и суммы.
   - Опции: отправка фотографии чека или нажатие кнопки `⏩ Пропустить чек` (`skip_payment_photo`).
4. **Финализация**:
   - Данные отправляются микросервису `Accountant` через событие/запрос `create_payment`.
   - Создается запись в таблице `Payment` со статусом `unconfirmed`.
   - Пользователь получает сообщение о успешной отправке на проверку администратору.

## 3. Права доступа и безопасность
- Взаимодействие доступно как администраторам, так и зарегистрированным арендаторам (чьи `telegramId` присутствуют в базе данных бота `prisma.user`).
- Попытки неизвестных пользователей запустить флоу блокируются на уровне Guard Middleware.
